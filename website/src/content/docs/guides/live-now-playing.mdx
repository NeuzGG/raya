`NowPlayingFeed` lets your website show what your bot is playing right now: track, artwork, progress and server. It updates the moment a song changes, pauses or ends.

Only servers you opt in are shown, and **no usernames or requesters are ever shared**.

## How it works

Your website can't talk to Discord or Lavalink directly, so your bot shares the data:

```
Lavalink  →  your bot (Raya + NowPlayingFeed)  →  your website (live cards)
                        GET /now-playing          JSON snapshot
                        GET /now-playing/stream   live updates (Server-Sent Events)
```

## Set up the feed

<Steps>

1. **Decide which servers are public.** `publish` gets a guild id and returns how that server should appear, or `null` to keep it private. The simplest opt-in is a list of guild ids:

   ```js title="bot.js"
   const { NowPlayingFeed } = require('raya.js');

   const PUBLIC_SERVERS = new Set(['123456789012345678', '234567890123456789']);

   const feed = new NowPlayingFeed({
     port: 8787,
     cors: 'https://neuzgg.github.io', // your website origin
     publish: (guildId) => {
       if (!PUBLIC_SERVERS.has(guildId)) return null;
       const guild = client.guilds.cache.get(guildId);
       return guild ? { name: guild.name, icon: guild.iconURL() } : null;
     },
   });

   await raya.use(feed);
   ```

2. **Check it works.** Play something in a public server and open `http://localhost:8787/now-playing`. You should see JSON with the track.

3. **Make it reachable over HTTPS.** Websites on HTTPS (like GitHub Pages) can't load `http://` feeds. Put the feed behind HTTPS, for example:
   - a reverse proxy (Caddy, Nginx) on your bot's server with a domain, or
   - a Cloudflare Tunnel: `cloudflared tunnel --url http://localhost:8787`

4. **Point the website at it.** In `website/src/site.mjs` set `liveFeed: 'https://bot.example.com/now-playing'`, or set the `PUBLIC_LIVE_FEED_URL` environment variable when building. The **Playing right now** section appears on the landing page.

</Steps>

<Aside type="tip" title="Let server admins opt in">
Instead of a hard-coded list, add a command like `/live on` that saves the guild id to your database, and check it in `publish`. `publish` is called often, so read from a cache (a `Set` or `Map`) rather than querying the database each time.
</Aside>

## Use your existing web server

Leave out `port` and mount the feed on a server you already run:

<Tabs>
  <TabItem label="Express">
    ```js
    const feed = new NowPlayingFeed({ publish });
    await raya.use(feed);

    app.get(['/now-playing', '/now-playing/stream'], (req, res) => feed.handle(req, res));
    ```
  </TabItem>
  <TabItem label="node:http">
    ```js
    http.createServer((req, res) => {
      if (feed.handle(req, res)) return; // handled by the feed
      res.writeHead(404).end();
    }).listen(3000);
    ```
  </TabItem>
</Tabs>

## Show it on any website

You don't need this docs site. The feed works with a few lines of plain JavaScript:

```html
<ul id="now-playing"></ul>
<script>
  const list = document.getElementById('now-playing');
  const feed = new EventSource('https://bot.example.com/now-playing/stream');

  feed.addEventListener('snapshot', (event) => {
    const { players } = JSON.parse(event.data);
    list.replaceChildren(
      ...players.map((p) => {
        const item = document.createElement('li');
        item.textContent = `${p.server.name}: ${p.track.title} by ${p.track.author}${p.paused ? ' (paused)' : ''}`;
        return item;
      }),
    );
  });
</script>
```

Always set feed data with `textContent`, not `innerHTML`, because track titles come from the internet.

## Data format

```json
{
  "players": [
    {
      "id": "123456789012345678",
      "server": { "name": "Lofi Lounge", "icon": "https://cdn.discordapp.com/icons/..." },
      "track": {
        "title": "Neon Tide",
        "author": "Lumen Coast",
        "uri": "https://open.spotify.com/track/...",
        "artworkUrl": "https://i.scdn.co/image/...",
        "source": "spotify",
        "duration": 192000,
        "isStream": false
      },
      "position": 64250,
      "paused": false,
      "speed": 1,
      "loop": "off",
      "queueSize": 3
    }
  ],
  "totals": { "playing": 12 },
  "time": 1789000000000
}
```

`position` is the position when the snapshot was sent. To animate a progress bar, add `(now - receivedAt) × speed` while not paused. A new snapshot arrives on every track change, pause, seek or stop, and when position drifts by more than 2 seconds.

## Options

| Option | Default | Description |
| --- | --- | --- |
| `publish` | required | `(guildId) => { name, icon? } \| null`. Return `null` to keep a server private |
| `port` | – | Start a standalone server on this port |
| `host` | all interfaces | Interface for the standalone server |
| `path` | `'/now-playing'` | Snapshot URL; the stream is at `path + '/stream'` |
| `cors` | `'*'` | `Access-Control-Allow-Origin` |
| `interval` | `2000` | ms between checks for pauses, seeks and drift |
| `maxClients` | `500` | Maximum simultaneous stream connections |
| `includeTotals` | `true` | Include the number of playing servers (a count only) |

| Member | Description |
| --- | --- |
| `feed.url` | Standalone server URL once listening |
| `feed.connections` | Connected stream clients |
| `feed.snapshot()` | Current public data |
| `feed.refresh()` | Push an update to every client now |
| `feed.handle(req, res)` | Serve the feed on your own server; returns `false` for other URLs |
